# DSH Bot 体验整改计划

目标：功能不减少、不新增大功能，把现有能力做得**更容易看懂、更容易点、更少误操作**。

## 原则

1. **不新增功能面**：只修现有流程、布局、反馈、文案、状态和可访问性。
2. **先修阻塞体验**：重叠、点不到、点了没反应、不知道发生了什么，优先于视觉美化。
3. **一次只改一类**：每轮集中一类问题，避免大改引入回归。
4. **可验证**：每个修复要有复现路径、验收标准和回归检查。
5. **不碰数据**：保留会话、群、例程、记忆和设置；QQ 保持默认关闭。

## 阶段

### P0：聊天核心体验

范围：

- 进入会话默认最新；
- 「回到最新」位置、层级、点击和消失；
- 滚动区与输入区/成员标签/待处理卡片不重叠；
- 发送后、运行中、结束后的滚动行为一致；
- 待回答、审批、checkpoint 卡片不遮挡输入框。

验收：

- 1024 / 1280 / 1920 宽度下，按钮和输入区不重叠；
- 点击「回到最新」一次即回到底部并隐藏；
- 切换会话后直接停在最新，不需要手动点；
- 长会话、流式输出、审批弹层下不跳动。

### P1：表单与设置

范围：

- Bot 编辑、群编辑、例程编辑、通知/预算设置；
- 保存中/成功/失败反馈；
- 字段校验和错误提示；
- 危险操作二次确认；
- 取消、关闭、返回不丢输入。

6.20 已完成 Bot 编辑器、群编辑器的未保存修改确认和 Esc 关闭保护；例程编辑仍待处理。

6.21 已完成例程编辑器的未保存确认：取消、切到新建/其他例程、应用模板都会先提示。

6.22 已把通知 + 预算合并保存改成显式脏检查：没有修改时保存按钮禁用；通知成功但预算失败会说明“通知已保存，预算失败”，不再一句“保存失败”误导。

验收：

- 每个保存动作有明确状态；
- 错误信息说明“哪里错、怎么改”；
- 取消后不产生半成品；
- 删除/覆盖类操作需要明确确认。

### P2：导航、空状态和加载

范围：

- 侧栏会话列表、群、例程、记忆、技能入口；
- 空状态说明下一步；
- 加载骨架/占位；
- 失败卡片提供重试、换办法、复制诊断；
- 搜索和跳转结果可理解。

验收：

- 新用户不看文档也知道下一步点哪里；
- 空列表不是空白；
- 失败不是只有一句“出错了”；
- 搜索命中能定位并高亮。

### P3：响应式与可访问性

范围：

- 1024/1280/1920、100%/125%/150% 缩放；
- 右侧 Deck 不盖住主操作；
- 键盘 Tab 顺序、Esc 关闭、focus ring；
- 小字号和低对比度文字；
- 触控目标不小于可点击尺寸。

验收：

- 所有主要操作可键盘完成；
- 弹层打开后焦点不跑到背景；
- 没有文字被截断到不可读；
- 窄窗口不出现横向滚动或控件重叠。

### P4：收口

- 更新 `docs/UI_DESIGN.md` 和截图；
- 增加 UI 回归检查（静态布局/关键交互）；
- CHANGELOG、README、release notes 对齐；
- 发布最终 UX 版本，停止继续加交互。

## 每轮输出

3. 修复点；
4. 验收证据；
5. 回归风险；
6. 版本和发布链接。

## 验收证据

- 每个修复提供复现路径和尺寸；
- 至少覆盖 1024×768、1280×720、1920×1080；
- 不依赖截图猜布局：同时记录 DOM/CSS 依据；
- 不操作外接显示屏；用户只提供笔记本屏幕截图时以其为准。

## 不做

- 不重做整套视觉；
- 不新增聊天/群/例程功能；
- 不改模型路由和权限模型；
- 不为“看起来高级”增加动画、渐变或装饰；
- 不再引入浏览器扩展或本地桥。
