# 团队模板：老大 + 专家

DSH Bot 自带一套可直接用的三人团队。你只需要和「老大」对话，它自己判断要不要派活、派给谁、验收结果，再向你汇报。

| 角色 | 名字 | 职责 | 默认权限 / 模式 | 工作区 |
|---|---|---|---|---|
| 老大（lead） | 老大 👑 | 只跟你对话：判断、拆解、派活、验收、汇总 | 标准 / 交互 | `DSH_HOME` |
| 专家 | 磁盘清理 🧹 | 磁盘空间：盘点、缓存、临时文件、旧备份、回收站、重复文件 | 管理员 / 无人值守 | `DSH_HOME/dsh-bot-team/disk` |
| 专家 | 大学事务 🎓 | 课程、作业、考试、绩点、选课、论文、材料、日程 | 标准 / 无人值守 | `DSH_HOME/dsh-bot-team/university` |

> 专家是无人值守的：它们不会停下来问你，缺信息时按最合理、最可恢复的假设继续，并在回执里列出假设。这样你只需要面对老大。

## 一键建立

三种方式，效果一样，幂等（重复执行不会覆盖你改过的设定）：

1. **界面**：DSH Bot 左侧栏底部「团队模板」。
2. **CLI**：

   ```powershell
   node dsh-bot/scripts/bot_cli.mjs team init
   node dsh-bot/scripts/bot_cli.mjs team list
   node dsh-bot/scripts/bot_cli.mjs team assignments
   ```

3. **API**：`POST /dsh-bot/api/team/bootstrap`。

建立后会自动创建一个「和老大对话」的私聊，并切到老大。

## 一次派活是怎么走的

```text
你 → 老大：这次只查 C 盘剩余空间
老大：判断这是磁盘活 → 调 bot_delegate("磁盘清理", 完整任务书)
      → 立刻回你：已派给磁盘清理，完成后我汇总（本轮结束）
磁盘清理：在自己的 DSH Session 里执行 → 给出结果 + 命令证据 + 耗时
      → 宿主自动把【任务回执】送回老大的对话
老大：验收回执（必要时自己只读复核）→ 向你汇报结果、证据、下一步
```

- 每次派活都会创建一条独立的「派活 · 成员：任务」线程，保留完整工具轨迹，随时可点开审计。
- 老大的对话里会出现「已派给 X · 进行中 / 已完成」卡片；完成后卡片更新为结果摘要。
- 同一次请求最多派 3 次；连续派两轮仍没结果就会停下来汇报，避免套娃。
- 老大自己只做三类事：一句话能答的判断、读取/汇总已有结果、验收复核；执行类工作必须派给专家。

## 安全边界

- 磁盘清理只能删：临时目录、应用缓存、更新包、日志、回收站、明确的旧备份（保留最新 1–2 份）。
- 游戏库、项目源码、文档/照片/视频、DSH 与 WorkBuddy 数据、未确认目录：只报告不删。
- 禁止 `format` / `diskpart` / `Clear-Disk` / `Initialize-Disk` / 根目录 `rd`；写操作前宿主会做安全快照。
- 不可逆删除要求先列清单；优先回收站。
- 大学事务：对外提交、发邮件、缴费、报名只做草稿，明确标出需要你确认；成绩/证件内容不外传。

## 自定义

- **改人设**：Bot 编辑 → 额外设定；或直接改 `docs/TEAM.md` 之外的模板常量再重跑（模板只补空字段，不覆盖已有内容）。
- **换专家**：把某个 Bot 的角色设为「老大」，其余设为「队员」，老大的系统提示会自动带团队名册并启用 `bot_delegate`。
- **加成员**：新建 Bot，在团队模板初始化后手动补一条人设即可；老大名册会自动包含所有 Bot。
- **群聊协作**：想要「多人在同一频道里讨论」，用群聊 + `@点名` + `bot_dispatch`；老大私聊更适合「我只提需求，你去安排」。

## 现有员工做不了：老大自己招人

老大有一个 `bot_hire` 工具。当任务没有对口成员时：

1. 先 `bot_hire(name, persona, tagline, effort, model)` 新建专家；
2. 新 Bot 自动获得 `DSH_HOME/dsh-bot-team/<名字>` 工作区、长期记忆、standard 权限、无人值守；
3. 然后立刻 `bot_delegate` 把活派给它；
4. 新成员出现在 Bot 胶囊里，并加入下一次晨会。

限制：一次用户请求最多招 2 个；团队总上限 12 个；不能重名；新成员默认 flash + low，需要时可在派活里升级。

实测：让它做「本机已安装软件清单」，它自己招了「软件盘点 📦」，产出 469 条记录（传统软件 123 / UWP 147 / 框架包 55 / 系统组件 142 / winget 2），验收后汇报。

## 每天第一次打开 DSH：全员晨会

- 当天第一次打开 DSH（或第一次打开 Bot 页）时，自动创建 **☀️ 晨会 · 全员** 群，把所有 Bot 拉进来。
- 每位成员先发言：用自己最近 36 小时的运行记录，3 条以内总结「做了什么 / 结果或证据 / 下一步」；没有记录就写“最近没有任务”，不编造。
- 老大最后出晨会纪要：昨天各自做了什么、风险/阻塞、今天优先级、需要用户拍板的事。
- 一天一次，日期记在 `state.meeting.lastDate`；`meeting status` 可查，`meeting run` 可手动补开。
- 晨会群里的普通消息默认只发给老大，由老大派活；`@某人` 才会直达该成员。
- 任何群成员的一轮结束都会把最终回复写进群消息（失败写原因），agent 被回收也不会丢；晨会不触发 QQ 通知。
- 群成员上限 8，晨会按顺序逐个发言，不会同时开一堆 agent。

## 模型与思考强度

| 角色 | 模型 | 强度 | 理由 |
|---|---|---|---|
| 老大 | `deepseek-v4-pro` | `max` | 判断、拆解、验收、汇总，值得用最好的 |
| 队员默认 | `deepseek-flash` | `low` | 执行具体任务，成本优先 |
| 难题升级 | 派活时 `model: deepseek-v4-pro` | `max` | 只有复杂排障/分析才升级 |

`bot_delegate` 支持 `effort: low | high | max`：简单读取用 `low`，多步脚本用 `high`，复杂分析用 `max`。每个 assignment 是独立线程，模型/强度只影响这一次派活，不会污染其他任务。

- 自建员工：老大招「软件盘点 📦」并派活，产出 469 条已安装软件清单（Markdown + CSV），验收后汇报。
- 晨会：首次打开自动触发；5 位成员按顺序发言（磁盘清理/大学事务第一轮因 `medium` 不被 flash 支持而失败，改为 `low` 后第二轮全部发言），老大用 pro/max 出纪要；`lastDate` 保证一天一次。

## 常见问题

**为什么老大有时自己做？**
提示词要求「用户点名成员就必须派」，但模型仍可能在极小任务上直接做。可以在对话里明确说「必须派给磁盘清理，不要自己做」；或者把老大的人设再收紧。

**专家会不会乱删东西？**
磁盘清理有独立人设和硬性清单；宿主在执行 `Remove-Item` 等破坏性操作前会写快照，并拒绝磁盘级操作。仍然建议第一次先让它「只盘点、不删除」。

**能同时有多个老大吗？**
可以，但不建议：每个老大都有自己的团队名册和派活计数，容易出现重复派活。
